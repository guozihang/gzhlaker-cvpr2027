\section{Introduction}
\label{sec:intro}
Video copy localization (VCL) returns the corresponding temporal intervals in a query
video and a reference video. Unlike whole-video retrieval, it must identify partial copies
and their boundaries on both axes, despite cropping, overlays, re-encoding or speed
changes~\cite{vcsl2022,transvcl2023}. We study the pairwise task given fixed pretrained
ISC descriptors, rather than searching a video library.

Classical methods use geometric voting or temporal alignment; learned methods detect copy
patterns in similarity maps or enhance frame interactions before
localization~\cite{vcsl2022,spd2021,transvcl2023}. Dense comparison considers $MN$ frame
pairs for sequences of $M$ and $N$ descriptors; chunking reduces peak allocation, but still
requires the comparisons inside the processed chunk pairs. When copies occupy a small part
of the time plane, discovery and boundary refinement need not use the same domain.

FastVCL separates them. Sparse mutual matches support local affine temporal tracks;
dual-axis support checks and gap splitting produce finite tubes, within which full-resolution
features are compared and aligned. Extension moves the search beyond the outer anchors but
does not guarantee that those boundaries are recoverable. Sparse proposals may miss a copy,
and local alignment cannot create evidence outside its search domain.

Mutual matching, RANSAC and local alignment are established tools~\cite{liu2023sam,smith1981};
coarse-to-fine video matching also has precedents~\cite{tian2013,wang2026mltdedup}. The
assembly alone is insufficient evidence of a new contribution. We test three hypotheses:
\begin{itemize}
\item \textbf{H1: candidate coverage.} Reducing coarse dot products retains useful candidate
coverage, including on short segments.
\item \textbf{H2: boundary recovery.} On identical candidates, in-tube local alignment improves
endpoints without obtaining the apparent gain solely by dropping difficult segments.
\item \textbf{H3: system benefit.} Less alignment work improves measured quality--cost trade-offs
on the same hardware after proposal, transfer and post-processing costs are included.
\end{itemize}
A strong simple sparse-to-band baseline and controlled changes are necessary to distinguish
mechanism gains from larger budgets or different candidates.

\paragraph{Scope and current contributions.}
This draft provides (i) a finite-tube specification and cost accounting that separates
quadratic coarse arithmetic from bounded refinement, (ii) restart-semantics counterexamples
and controls for candidate coverage and boundary recovery, and (iii) a proposed evaluation
protocol with explicit completion, threshold and timing rules. These are methodological
artifacts; empirical benefit and novelty relative to the baseline remain unresolved.
``Training-free'' refers to the core: ISC is pretrained and validation labels select
parameters. A proposed \texttt{seltive model} branch adds frame-based verification
(Section~\ref{sec:method-selective}).

\paragraph{Evidence status.}
The code is a preliminary prototype whose continuation rule differs from the DP specified
here. No frozen benchmark or GPU timing supports the paper; tables retain visible
placeholders, and development/synthetic checks are only in the supplement. ``Fast'' is a
project name, not a speed claim. The supplement contrasts the dense and sparse domains
conceptually.
